# 古籍指针预编号设计

日期：2026-08-26  
状态：已确认  
适用范围：`web/factory/` 本地候选工厂

## 问题与证据

`name-factory-v3` 已经阻止模型直接填写姓名和出处事实，但第一次真实 smoke 显示，模型无法可靠心算 `normalizedText` 的 Unicode 下标。两组指针均合法，却把理由中想选的“户若”“野兰”编译成了“在待”“在怀”。本地编译与语义审核正确阻止了错误发布，但位置误差会浪费候选和审核调用。

## 方案

保留“模型只返回两个位置、本地生成姓名和证据”的安全边界，在每个 passage 输入中增加紧凑的 `indexedText`：

```text
[0]七 [1]月 [2]在 [3]野 [4]八 [5]月 …
```

提示词要求模型从 `indexedText` 复制括号内编号，不再自行对原文计数。`text` 继续提供完整语境，`normalizedText` 继续作为本地权威正文；`indexedText` 只是两者的确定性编号视图。模型响应仍不得包含姓名、字符、出现次数、关系或证据说明。

为减少明显无效调用，本地虚词硬规则补充“在”。该规则只影响推荐候选，不影响全文搜索，也不把所有低姓名感字无限扩成黑名单；其余边界仍交给匿名语义和姓名感审核。

## 版本、恢复与费用

提示词版本升级为 `name-factory-v4`，确保旧 v3 缓存和检查点不会误用。实现后先运行无网络测试与构建，再执行一次隔离输出、最高 1 元的 smoke。smoke 产物写入本地报告目录，不覆盖当前网页的 25 个人工核实候选；是否扩量需依据指针一致性和名字质量另行决定。

## 验收标准

- 输入中的每个 `indexedText` 与 `normalizedText` 逐字、逐下标一致；
- 提示词明确要求复制编号而不是自行计数；
- 生成响应 Schema 仍不含姓名和证据事实字段；
- “在怀”等含“在”的组合在本地硬规则阶段淘汰；
- 全量测试、类型检查、构建和安全测试通过；
- 第二次 smoke 不修改当前网页候选文件，费用不超过 1 元，并报告指针与理由是否一致。
