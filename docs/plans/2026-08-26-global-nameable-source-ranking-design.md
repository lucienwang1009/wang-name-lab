# 全库质量优先取材与最终短名单设计

日期：2026-08-26  
状态：基于 v7 小批校准修订  
适用范围：`web/factory/` 本地候选工厂

## 实证问题

v7 校准从 70 部全文库每书最多取 4 段，共审核 128 个有效组合。程序发布 10 个，但人工逐名复读发现，其中多个仍偏硬、像词组或只是“没有大错”。主要原因不是全文库太小，而是推荐取材把“全库可搜”误解为“每部书必须平均产出候选”。法规、训诂、史传和诗赋因此被给予相同的生成配额，迫使模型从姓名机会很弱的句段中勉强取字。

## 分开两种覆盖

- 全文搜索与典籍核实继续覆盖全部 70 部古籍，不删书、不删原文。
- 推荐候选对全库的合格窗口统一排序，不再为每书保证产出名额。
- 书目、作品和用字多样性作为软惩罚与集中度上限，防止少数大书垄断，但不让低质量来源借“覆盖”挤走高质量来源。

CLI 现有 `passages-per-book` 参数在兼容期继续表示总取材规模：总目标仍约为该值乘以有候选的书目数，但不再是单书硬配额。

## 全局动态 MMR

先按现有候选窗口质量分建立有界的全局候选池，再逐个选择：

```text
当前分 = 原句可命名质量
         - 与已选来源的用字相似度惩罚
         - 同作品重复惩罚
         - 同书已选数量的渐进惩罚
```

每选中一段后，只需用该段更新其余候选的最大相似度，无需重复扫描全部已选集。单书与单作品另有随总目标变化的宽松上限；这些上限只防止垄断，不保证每书入选。

## 最终短名单语义

数值门槛仍用于拦截低分项，但不把模型的“勉强 approve”当作最终质量证明。对抗审核的 approve 重新定义为：审查者真的愿意把该名放进面向家长的稀缺短名单，而不是仅仅“可以使用”。

若批评中已确认存在偏刚、偏中性、像普通词组、旧式熟名、明显平调、需要额外解释才像姓名或网名感，应当 reject，不再把它们统称为“轻微取舍”。`manual-review` 仅保留给方言、真实人物碰撞等当前资料无法确定的事实风险。

`name-factory-v8` 作为新审计版本，不复用 v7 的生成与审核缓存。

## 验收

- 极弱书目不再因轮询配额必然入选；
- 高质量书目可以获得多个名额，但不能超过集中度上限；
- 同作品和高度重复用字仍被 MMR 降权；
- 全文库 70 部书的搜索及核实覆盖不变；
- 新小批校准不覆盖公开候选，费用不超过当次硬上限；
- 对通过者逐名人工复读，若仍大量出现“仅可用但不值得推荐”，继续校准而不正式扩量。
