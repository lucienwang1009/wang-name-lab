# 个性化古籍寻名方法论 V2 设计

日期：2026-08-25  
状态：已确认，采用直接替换旧方法并复用现有古籍库

## 目标

把当前“古籍相邻字组合 + 人工权重总分 + 随机展示”的流程，直接替换为一套可解释、可学习并兼顾候选多样性的寻名系统。现有 70 部古籍的书目、全文、段落索引、来源链接和全文搜索继续使用；旧的文化总分、A级固定巨额加分、女性感硬阈值以及玉/影/绍固定加分停止参与推荐。

系统需要同时满足两个看似冲突的目标：原始候选覆盖尽可能广，默认推荐又必须保持较高质量。因此采用“宽进、分级、窄出”：大量自动组合保留在原始候选和全文搜索中，只有通过语义核验与硬性排雷的候选进入默认推荐。

## 核心原则

系统把四件事分开记录，不再提前揉成一个客观总分：

1. **典籍证据**：能否证明名字与原文存在明确关系。
2. **名字质量**：完整姓名在音、形、义和日常使用上的表现。
3. **个人适配**：是否符合当前家庭通过选择表现出的审美。
4. **传统参考**：实际出生后的八字、五行等民俗记录。

典籍证据强不自动代表名字质量高；家族纪念意义强也不能伪装成原文成词。个人适配只代表“适合这个家庭”，不得显示成普遍有效的姓名分数。

## 构建期数据流

现有古籍构建脚本继续生成书目、段落和全文索引，同时生成新的原始候选库：

```text
古籍段落
  → 提取连续双字、句内间隔、首尾/尾首、对偶并列、篇内同意象
  → 合并同名的全部出处
  → 识别虚词、专名残片、否定或负面上下文
  → 生成语义核验状态及名字级特征
  → 输出“可推荐候选”和“仅搜索候选”
```

候选证据分为四类：

- `exact-phrase`：原文连续出现，且在上下文中能形成完整词义。
- `clause-related`：来自同一句，存在明确的并列、对偶、修饰或首尾关系。
- `passage-related`：来自同段或同篇，意象和语义方向一致。
- `cultural-recomposition`：来源透明的文化或家族重组，不宣称原文存在该词。

自动提取但无法证明语义完整的组合标记为 `search-only`。它们可以在典籍搜索中被查到，但不得进入默认推荐。

## 硬性排雷

推荐池候选必须先通过以下门槛：

- 名字用字属于通用规范汉字范围；
- 原典上下文没有明显死亡、讽刺、贬义、刑罚或强烈战争风险；
- 与姓氏“王”连读没有稳定而明显的负面谐音；
- 多音、误读、输入和书写成本没有超过家庭接受范围；
- 取字路径、书名、篇章和来源链接可以复核；
- 没有必须排除的公众人物或强势虚构角色完整姓名碰撞。

门槛不能被其他指标的高值抵消。可调门槛必须保留原因，允许家庭以后修改接受范围。

## 名字特征

每个可推荐候选具有归一化到 `0..1` 的名字级特征，而不是简单平均两个汉字的分组代理值。第一版使用可解释的规则和人工核验种子，特征包括：

- 风格：`classical`、`graceful`、`gentle`、`bright`、`austere`、`modern`。
- 使用：`pronounceable`、`writable`、`recognizable`、`uncommon`。
- 关系：`familyMeaning`、`exactPhrasePreference`、`recompositionPreference`。
- 质量说明：整体语义、完整拼音、声调、主要风险与核验状态。

“女性感”不再作为硬阈值，而由柔和、端雅、明丽、清峻等连续风格共同表达。实际重名数据不可用时，`uncommon` 必须注明是代理估计，不能宣称为真实全国重名率。

## 个人偏好学习

首次使用展示 8 组快速二选一。校准样本从已核验种子中选择，保证每组基础质量接近、主要风格差异明显，并覆盖古典感、柔和度、独特性、易用性、直接典故与重组典故等轴线。

偏好模型使用本地可解释的线性效用模型：

```text
personalFit(candidate) = sigmoid(weights · candidate.features)
```

选择 A 胜过 B 时，使用成对逻辑更新：

```text
delta = features(A) - features(B)
p = sigmoid(weights · delta)
weights += learningRate × (1 - p) × delta
```

收藏和明确不喜欢是强信号，二选一胜负是中等信号，加入对比是弱正向信号，跳过不更新，“都不喜欢”把两者记为负向样本。不使用停留时长等噪声较高且不透明的行为。

所有反馈和权重只保存在浏览器 `localStorage`。界面解释推荐原因时展示贡献最大的 1–3 个特征，不展示伪装成客观结论的百分制总分。

## 多样性重排

先计算个人适配，再使用最大边际相关性（MMR）贪心选择一轮 12 个名字：

```text
selectionValue =
    0.75 × personalFit
  - 0.25 × maxSimilarityToSelected
  - exposurePenalty
```

候选相似度由风格接近、共享汉字、相近读音、相同典籍和相同取字方式构成。首版权重为 45%、20%、15%、10%、10%，作为可测试常量集中管理。

每轮采用 `7 + 3 + 2`：7 个当前高适配候选、3 个适配良好但明显不同的候选、2 个模型尚不确定的探索候选。并施加以下组批约束：

- 同一汉字最多出现 2 次；
- 完全同音最多保留 1 个；
- 同一意象类别最多 3 个；
- 至少覆盖 3 种主要风格；
- 至少覆盖 2 种取字方式；
- 已明确排除的姓名不再展示。

若严格约束无法凑满 12 个，只能按固定顺序放宽多样性约束，绝不放宽规范字、负面语境等安全门槛。

## 页面与交互

旧发现流程直接替换为四个区域：

1. **偏好校准**：首次 8 组二选一，支持左、右、都不喜欢和跳过。
2. **名字发现**：每轮 12 个个性化且多样的名字，支持“综合适配、典故扎实、清雅少见、日常好用、家族意象”视角。
3. **名字详情**：展示完整读音、整体含义、原文与上下文、取字方式、独立指标、主要取舍和推荐理由。
4. **典籍搜索与最终清单**：保留 70 部全文搜索、收藏、排除、对比和深链接。

人工精选候选继续作为已核验种子，但必须重新映射到新结构，不继承旧分数。现有收藏姓名、对比名单和出生资料迁移保留；旧排序、旧分数和旧随机批次丢弃。

## 八字与传统参考

出生信息仍在本地保存。实际出生时间和地点确认前，传统参考权重为 0；确认后最高为 10%。系统记录采用的时间口径、四柱、用神方向和判断理由，但不自动执行“缺什么补什么”，也不加入五格笔画吉凶。传统参考不能覆盖任何硬性排雷结果。

## 错误与降级

- 新候选静态资源加载失败时，显示可重试错误，不回退到旧机械组合。
- 偏好资料损坏时，保留收藏和出生信息，重置模型权重并重新校准。
- 候选缺少完整特征时，只允许出现在搜索结果中。
- 全文搜索不可用时，名字详情仍展示构建期保存的核验原句和来源链接。
- 旧 `localStorage` 自动迁移到版本化结构；无法识别的字段忽略而不是阻断启动。

## 验收标准

- 默认推荐中不存在仅因字符相邻而入选、但没有完整语义说明的名字。
- 典籍证据、名字质量、个人适配和传统参考分别展示。
- 完成 8 组校准后，推荐顺序能随选择产生可预测变化。
- 一轮 12 个名字满足共享字、同音、类别和风格多样性约束。
- 同一输入、同一偏好和同一语料版本产生确定性结果。
- 收藏、对比和出生资料可以从旧版本迁移。
- 全文搜索、姓名深链接和 GitHub Pages 静态部署继续可用。
- 单元测试、类型检查、生产构建及桌面/移动端视觉检查全部通过。
