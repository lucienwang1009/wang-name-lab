# 候选友好古籍取材窗口设计

日期：2026-08-26  
状态：已确认  
适用范围：`web/factory/` 本地候选工厂

## 问题

第二次真实 smoke 已证明预编号指针能够准确选择目标字，但候选仍为零。根因转移到取材层：旧 `passageNameabilityScore` 按“月、兰、英、若”等正向单字的出现次数给整段加分，再按每书最高分轮询。它不能区分“句中存在自然双字机会”和“整段只是堆有若干吉祥字”，也不会限制模型从两篇无关原文各取一字。因此《七月》和《悯上》被选入首批，模型准确生成的“宇明”仍然跨篇、生硬且偏男性化。

## 选择的方案

不增加一次付费 LLM 筛选，也不建立覆盖有限的人工白名单。由本地程序从每个原始 passage 派生候选友好窗口：按古典标点切成单分句和相邻双分句，保留窗口在完整 `normalizedText` 中的绝对起止位置。窗口只用于选材和提示，原始 passage ID、全文、字符出现序号和发布引用保持不变。

每个窗口枚举距离 1–4 的双字机会。两个字必须来自现有 500+ 可用字典、互不相同且不是确定虚词；评分综合连续取字、女性感、易用性、适度少见度和语境长度，并排除明显负面、战争、注释噪声窗口。passage 分数由最好的少量窗口决定，而不是累加同一个吉祥字的出现次数。

## 多样性与生成边界

每书仍保留配额，但配额内采用确定性 MMR：基础质量减去与已选窗口的用字 Jaccard 相似度和同作品重复惩罚，避免“月、清、兰”或同一篇章垄断首批。提示词只发送每段最高质量的少量窗口，`indexedText` 使用原始全文的绝对编号。

自动生成阶段要求 first 与 second 来自同一个 passage。允许连续、同句首尾、对偶和同篇重组，但不再自动把两篇无关文字拼成名字。底层指针编译器仍保留跨篇关系能力，供人工家族重组或未来独立、显式的文化重组流程使用。

## 失败与审计

- passage 没有任何合格双字窗口时不进入生成池；
- 模型选择窗口外位置、跨 passage、越界或同一位置时按指针问题审计，不进入付费审核；
- 校准批次连续无候选时继续沿用安全停止，不降低语义、姓名感或证据门槛；
- 提示词升级为 `name-factory-v5`，旧缓存与检查点不能复用；
- smoke 输出继续隔离在报告目录，不覆盖网页候选。

## 验收标准

- “柔嘉维则，令仪令色”评分稳定高于重复月份但缺少自然组合的句段；
- 派生窗口的绝对下标可由本地全文逐字回查；
- 负面窗口和无双字机会的 passage 不进入生成池；
- MMR 在质量接近时优先不同用字和不同作品；
- 自动流水线拒绝跨 passage 指针，但底层编译器仍能表示跨篇关系；
- 全量测试、类型检查、构建、安全检查和零请求 dry-run 通过；
- 隔离 smoke 中目标字与指针一致，并至少进入姓名感审核，或报告具体的新瓶颈而不扩量。
